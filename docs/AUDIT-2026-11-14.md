## Architecture found

| Layer | Current implementation |
|---|---|
| Website | One `index.html` with inline CSS and three JavaScript blocks; four property images and `CNAME`. No frontend framework or runtime build step. |
| Hosting | GitHub Pages deployment from `main`, custom domain in `CNAME`, HTTPS live URL. |
| API | One Apps Script `/exec` URL in `BOOKING_API`; GET `status` / `quote`; POST `requestBooking` and `stay.*` actions. Plain-text JSON POST avoids a preflight requirement. |
| Accounts | In-memory browser token; no local/session-storage persistence. Saved backend uses 30-minute cached sessions, customer IDs, authentication version invalidation, PBKDF2-SHA256 and rate limits. |
| Booking | Server quotation used by the UI. Saved backend recalculates under a script lock, generates UUID references and records agreement version/acceptance/time. Pending requests do not reserve dates. |
| Availability | Saved code blocks overlaps with `CONFIRMED`, `CHECKED_IN` and active blocked ranges. Adjacent checkout/check-in dates are allowed. |
| Payments | Customer claims are separate from verified money. Saved backend validates amount, date, size and file signature; checks a private Drive folder; deduplicates uploads; owner review updates balances and an audit log. |
| Changes/refunds | Server preview, acceptance and request IDs; owner review; snapshot/version checks; availability recheck for date changes. Refund recording is separate from the manual bank transfer. |
| Administration | Google Sheets custom menus in saved source. No separate web admin application in this repository. |

## Confirmed frontend defects corrected

1. **Guest details survived sign-out or session rejection.** Clear the displayed booking contact fields, account editor, login identifier and old confirmation details when resetting authentication.
2. **Search accepted past or incomplete date ranges.** Validate before applying a date-based search. Location-only search remains supported.
3. **Rental checks sent past dates to the API.** Reject those locally before the network call; server validation remains essential.
4. **Date minimum depended on the guest's timezone.** Use Malaysia calendar dates, including after midnight and across year boundaries.
5. **Transferred search dates left the checkout minimum stale.** Recompute it when opening the property and when clearing/changing check-in.
6. **Property/terms/confirmation dialogs lacked focus management.** Add dialog semantics, focus entry/restoration and Tab containment for the top dialog. Preserve nested terms closure and scroll locking.

Existing quote-generation race protection, the unauthenticated booking guard, and the in-flight submission guard were retained and regression-tested. Existing pricing, cancellation, payment and legal text were not edited.

### Quotas and failure handling

Google currently documents a six-minute script execution limit, 30 simultaneous executions per user and 1,000 per script. Daily quotas vary by account type and can change. The saved login/registration implementation also imposes its own shared authentication budget; benchmark its 600,000-iteration password computation and expected legitimate traffic in staging. Do not weaken password hashing to mask performance problems.

The public quote path reads multiple spreadsheet tables per request. Avoid production load testing. Validate rate handling, timeout recovery and duplicate prevention in staging. Google recommends flushing spreadsheet changes before releasing a script lock; the saved booking write does this. A lock cannot protect manual edits or a different script project.

References checked on 14 November 2026: [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas), [Apps Script Lock documentation](https://developers.google.com/apps-script/reference/lock/lock.html).
